# Plan: Every request in an agy home, and tool calling through an MCP bridge

**Goal** — Every request runs agy in a throwaway agy home with its system text in `AGENTS.md`, and a request with `AIFunction` tools has agy call them through a library-hosted MCP server, so `dotnet build -warnaserror`, the unit suite and the process suite pass and a fake agy acting as an MCP client runs a caller's tool body through the bridge.
**Status** — phase 1 done
**Research** — `research.md`

## Context

Spec: `spec.md` (buildable, 21/21 decisions confirmed). Today every request runs in the user's real agy home, the system text travels inside the prompt, and tools are refused (`RequestValidator`). The spec fixes two phases by a real dependency: the home and `AGENTS.md` change every request and are the base of the bridge (phase 1); the bridge, tool validation and cap come after (phase 2). The agy facts the work rests on are in `research.md` (HTTP bridge run, per-request home, `AGENTS.md`); they come from single runs, so each phase ends with an owner-run check against real agy that the executor writes but does not run. Project rules that bite: no `agy -p` or opt-in suite run without the owner, only `AgyProcessRunner` touches `Process`, only `InvocationBuilder` knows agy flags, `LogMessages` is the only logging and takes no content, no new package, warnings are errors, one commit per phase. Out of scope and staying out: a reusable template home, caller-supplied authentication settings for an isolated home, everything in the spec's Out list.

## Standing rules

- Tests are written together with the code. No red/green narration. After a guard is written, break it once and see its test fail.
- Conventional commits, one per phase, on the current branch; no new branch; never commit a secret.
- A run that spends model tokens is the owner's: write the opt-in test and its entry in `docs/antigravity-chat-client/owner-run.md`; do not run it.
- A missing tool is a halt: ask before installing anything.
- Run the unit and process suites before closing a phase; if the build dies with `Internal CLR error (0x80131506)`, run `dotnet build-server shutdown` and retry.
- When code shows the spec or a design document wrong, fix the document in the same commit and note it in the `Log`.
